# Image migration: Google Drive → self-hosted

The site currently serves ~110 images as public Google Drive "thumbnail" links
(`drive.google.com/thumbnail?id=...`), referenced across `images.js`,
`drive_photo_manifest.json`, the encyclopedia pages, district pages, blog, and
several `tools/firebase-import/**` package JSON files. Hotlinked Drive
thumbnails can be throttled/blocked by Google at scale, so we're migrating to
self-hosted files in the repo.

## Files here
- `full_drive_manifest.json` — every unique Drive file ID referenced anywhere
  in the codebase (110 total), with the display name(s) and the file(s) each
  one appears in. Generated by scanning all `.html`/`.js`/`.json` files in the
  repo (not just the old `drive_photo_manifest.json`, which only covered
  images.js/encyclopedia/packages and missed some encyclopedia + district
  page references).
- `fetch_drive_images.py` — resumable downloader. Reads
  `full_drive_manifest.json`, downloads each file from Drive, and writes
  `image_migration_map.json` (slug → local path) as it goes.

## How to run
Run this from a machine with real internet access — NOT from an environment
with restricted network egress, since it needs to reach `drive.google.com`.

```bash
cd tools/image-migration
pip install requests
python3 fetch_drive_images.py
```

Safe to run inside `tmux` — it's resumable (Ctrl+B D to detach, `tmux attach`
to come back; re-running skips anything already downloaded).

Output: `downloaded_images/` (the files) + `image_migration_map.json`
(slug → local path). Send both back for the next step: moving them into
`assets/images/places/` and rewriting every reference (`images.js`,
`drive_photo_manifest.json`, and any inline HTML) to point at local paths
instead of Drive URLs.
